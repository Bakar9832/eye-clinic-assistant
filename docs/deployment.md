# Deploying the live demo (free tiers)

```
Browser ──► Vercel (web app; passes /auth /me /chat /clinic /availability /appointment-types /staff on)
                 │
                 ▼
            Render: eye-clinic-api (NestJS) ──► Supabase Postgres (session pooler)
                 │  ▲ MCP tools
                 ▼  │
            Render: eye-clinic-agent (FastAPI) ──► Gemini API
```

Everything is in one region (Singapore) next to the database: a booking makes dozens of
queries, and from Pakistan each round trip to Supabase takes about 200 ms.

**Why Vercel passes API paths on instead of the browser calling Render directly:** the
browser then sees one site, so the login cookies are first-party (`SameSite=Lax`, no CORS
setup), and the CSRF rule (state-changing requests must be JSON) keeps working unchanged.

## 1. Database (Supabase)

Use the **Session pooler** connection string (Supabase → Connect → Session pooler). The
direct `db.<project>.supabase.co` address is IPv6-only on the free plan, which neither most
home networks nor Render's free plan can reach.

Migrations run on every API start (`prisma migrate deploy`), so the schema needs no manual
step. To fill the database with the demo's fake data, run the seed once **from your own
machine**, pointed at Supabase (it refuses to run with `NODE_ENV=production`, and it
**deletes all clinic data first**, so never run it again once people use the demo):

```powershell
cd api
$env:DATABASE_URL = "<the session pooler string>"
npx prisma migrate deploy
npx prisma db seed
Remove-Item Env:DATABASE_URL
```

### Passwords on the live database

The seed gives every made-up patient `SEED_PATIENT_PASSWORD` and every staff member
`SEED_STAFF_PASSWORD` (both from your `.env`). A database seeded before passwords existed
has none: set them one account at a time, without wiping anything. The password is read from
the environment, so it stays out of your shell history:

```powershell
cd api
$env:DATABASE_URL = "<the session pooler string>"
$env:NEW_PASSWORD = "<a password, at least 8 characters>"
npm run set-password -- staff admin@clinic.example
npm run set-password -- patient demo.patient@example.com
Remove-Item Env:NEW_PASSWORD, Env:DATABASE_URL
```

Staff can't sign up or reset their own password (their addresses are made up); this script
is how it's done. Patients sign up on the site with an emailed code, so **sign-up needs real
email** (the SMTP settings below).

## 2. API and agent (Render)

1. Render → **New → Blueprint** → connect the GitHub repo. Render reads `render.yaml` and
   creates both services (`eye-clinic-api`, `eye-clinic-agent`) on the free plan.
2. It asks for every value marked `sync: false` (table below). Make one long random string
   for `AGENT_SERVICE_KEY` and use it in **both** services:
   `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
3. After the first deploy, each service has a URL. Set the API's `AGENT_URL` to the
   agent's URL and the agent's `CLINIC_API_URL` to the API's URL, then redeploy both.

## 3. Web app (Vercel)

1. Vercel → **Add New → Project** → the same repo, **Root Directory `web`**. `web/vercel.json`
   sets the build (`npm run build`, output `dist`).
2. Render adds a suffix when a name is taken (this demo got `https://eye-clinic-api-3frf.onrender.com`). Put the API's real URL
   in `web/vercel.json` (seven lines) and push.
3. The web app has no environment variables: it only talks to its own site.

## Environment variables

**API** (`eye-clinic-api` on Render; locally from the root `.env`):

| Variable | Live demo | Purpose |
|---|---|---|
| `DATABASE_URL` | Supabase session pooler string (secret) | The database. |
| `NODE_ENV` | `production` | Secure cookies, no GraphQL introspection or GraphiQL, seed refuses to run. |
| `TRUST_PROXY_HOPS` | `2` (Vercel + Render) | How many proxies to trust for the visitor's IP, so per-IP limits count visitors. `0` locally. |
| `AUTH_SECRET` | generated by Render | Keys the hashes of login codes and session tokens. |
| `AGENT_TOKEN_SECRET` | generated by Render | Signs the 5-minute tokens the agent uses for one chat turn. |
| `AGENT_SERVICE_KEY` | secret, same as the agent's | Proves to the agent that a request comes from the API. |
| `AGENT_URL` | the agent's Render URL | Where the API sends chat turns. |
| `DEMO_MODE` | `false` | `true` enables the `/auth/demo` login (development and tests only; the web app has no button for it). |
| `SMTP_HOST` | `smtp-relay.brevo.com` | Email server (sign-up and reset codes). Empty = emails are written to the log instead. |
| `SMTP_PORT` | `2525` | Render's free plan blocks the usual mail ports (25, 465, 587); Brevo also listens on 2525. |
| `SMTP_SECURE` | `false` | `true` only for port 465. |
| `SMTP_USER`, `SMTP_PASSWORD` | Brevo's SMTP login and SMTP key (secret) | Brevo → SMTP & API → SMTP. |
| `EMAIL_FROM` | `Eye Clinic <a sender you verified in Brevo>` | Sender of clinic emails. Brevo refuses senders it hasn't verified. |
| `NOTIFICATIONS_EVERY_SECONDS` | `0` | How often reminders are sent; `0` = off (demo addresses are fake). |
| `RETENTION_EVERY_HOURS` | `24` | How often old chats, codes and sessions are deleted. |
| `PORT` | set by Render | The port to listen on (default 3000). |
| `NODE_VERSION` | `24` | Render's Node version. |

**Agent** (`eye-clinic-agent`):

| Variable | Live demo | Purpose |
|---|---|---|
| `LLM_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai/` | Any OpenAI-compatible API. Ollama locally: `http://localhost:11434/v1`. |
| `LLM_API_KEY` | your Gemini key (secret) | `ollama` for Ollama. |
| `LLM_MODEL` | `gemini-3.1-flash-lite` | `qwen3.5-9b-16k` for the local model. |
| `LLM_FALLBACK_MODEL` | unset | Tried when the main model keeps failing. |
| `LLM_REASONING_EFFORT` | `none` | Turns a thinking model's reasoning off. |
| `LLM_TIMEOUT_SECONDS` | `60` | How long one model call may take. |
| `AGENT_SERVICE_KEY` | secret, same as the API's | See above. |
| `CLINIC_API_URL` | the API's Render URL | Where the agent reaches the MCP tools (`/mcp`). |
| `AGENT_PROMPT` | unset (`full`) | `minimal` is the evals' baseline prompt. |
| `PYTHON_VERSION` | `3.14.3` | Render's Python version. |

**Local only** (development and tests, root `.env`): `SEED_PATIENT_PASSWORD` and
`SEED_STAFF_PASSWORD` (the seed's passwords), `TEST_DATABASE_URL` (wiped by the tests;
its name must contain "test"), `EVAL_DATABASE_URL`, `EVAL_MAX_LLM_CALLS_PER_MINUTE`,
`EVAL_GRADER_BASE_URL`, `EVAL_GRADER_API_KEY`, `EVAL_GRADER_MODEL`, `CLINIC_API_URL`.
`SUPABASE_*` lines in `.env` are notes; the code reads only `DATABASE_URL`.

## Free-tier limits

- **Render** puts a free service to sleep after 15 minutes without traffic; waking takes
  about a minute, and the first chat message after a quiet spell wakes both services.
  The reminder and clean-up jobs only run while the API is awake. 750 free hours a month are
  shared by both services.
- **Supabase** pauses a free project after a week without activity (resume it in the dashboard).
- **Gemini's** free tier allows a limited number of requests a day per model.
